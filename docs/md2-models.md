# MD2 entity previews

Heron Brush reads Quake II MD2 version 8 models referenced by entity definitions.
They use the same game/mod filesystem as MDL and OBJ: loose files, id PAK and
stored/Deflate ZIP/PK3. Embedded skin paths resolve in the game namespace first,
then relative to the model. Explicit absolute model paths can also resolve a skin
beside the chosen model. Packages are never extracted.

The preview decodes the first frame's byte vertices using its scale and translation,
keeps triangle winding and UV seams, computes bounds from drawn geometry and applies
the existing class scale/entity transform. Signed ST coordinates include the Quake II
half-texel offset. UV texels rescale when the decoded image dimensions differ from
the MD2 header, including the untextured fallback.

The first external skin can be Quake II's version-5, single-plane, 8-bit RLE PCX
with a trailing 256-colour palette, or a supported PNG/JPEG/TGA raster image. PCX
row padding is skipped and palette index 255 is transparent. Missing or unsupported
skins keep the geometry and use grey. The same bounded PCX decoder also serves map
material discovery from folders and mounted archives; see [game assets](game-assets.md).
Quake II WAL map materials are also supported with external PCX palettes.

The loader validates signed header fields, section bounds, frame lengths, triangle
indices, normal indices and finite frame transforms. Static preview limits follow
the original MD2 limits of 2,048 vertices, 4,096 triangles, 512 frames and 32 skins;
image dimensions are capped at 8,192 and decoded allocation at 64 MiB. PCX rejects
truncated RLE, zero runs, scanline overruns, unsupported planes/encoding and invalid
palette data. MD2's unused GL command section is range-checked but not interpreted.

Only frame 0 and skin 0 are shown. Model animation, frame/skin selection and the
MD2 normal lookup table are not implemented; lighting uses geometric face normals,
as existing MDL previews do. Static MD3 previews are now available separately; see [MD3 scope](md3-models.md). Additional PCX variants remain separate work. This adds entity previews, not a new mesh import
entry in the GUI or native Quake II gameplay export.

Format references are id Software's [qfiles.h](https://github.com/id-Software/Quake-2/blob/master/qcommon/qfiles.h)
and [image loader](https://github.com/id-Software/Quake-2/blob/master/ref_gl/gl_image.c).
No commercial game files are included. The self-authored two-frame pyramid and
PCX palette skin are generated by `examples/editor-checks/make_md2_fixture.py`.
The same files are supplied loose, in PAK and in deflated PK3 for reproducible tests.

## Verification

Reader tests cover transforms, bounds, UV scaling, skin fallback, TGA, PCX padding,
transparency and malformed/truncated inputs. ModelStore compares exact geometry
and pixels across loose files, PAK, PK3 and explicit absolute model lookup. A
Document integration test loads the Quake 2 profile, a model expression beginning
with `:`, a class scale of 2 and entity placement, then checks rendered triangles,
skin pixels and the bounding-box fallback when model drawing is disabled.

Offline regression suite on 15 October 2026: **1,458 passed, 14 ignored**, no
failures (`/tmp/heron-md2-full-tests.log`). Default desktop build and WASM check
passed (`/tmp/heron-md2-desktop-build.log`, `/tmp/heron-md2-web-check.log`).
Native Linux/wgpu preview loaded a PK3 pyramid with its PCX skin from an isolated
game directory and sibling FGD on a private Xephyr display. The screenshot was
visually checked: `/tmp/heron-md2-native/shots/preview.png`; startup log:
`/tmp/heron-md2-native/run.log`. The fixture contains two distinct frames; tests
require the first frame's bounds, not the shifted second frame. No engine was
installed and no commercial asset was downloaded.
