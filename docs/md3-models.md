# MD3 entity previews

Heron Brush reads Quake III MD3 version 15 for entity-definition previews. It
uses frame zero, retains every surface as a separate material, and decodes
signed fixed-point positions, normalized UVs and packed vertex normals. Bounds
come from drawn geometry. The existing entity origin, angle and class/model scale
apply to positions and normals.

The first shader name on each surface is resolved as a raster image through the
shared game/mod filesystem. An extensionless name tries TGA, JPG, PNG and JPEG.
Loose files and PAK/ZIP/PK3 assets follow existing priority rules and packages
remain unextracted. Explicit loose model paths also find textures beside the
selected model. Missing or undecodable textures retain grey geometry. UVs scale
to the actual decoded texture dimensions, including the grey fallback.

The reader checks signed counts and offsets, frame and surface bounds, section
overlap, surface signatures, triangle indices and finite UVs. Limits are 1,024
frames, 32 surfaces, 16 tags per frame and, per surface, 4,096 vertices, 8,192
triangles and 256 shader names. Unused frames, tags and shader records are
range-checked but not interpreted. Textures have bounded decoding and RGBA
conversion, with a 64 MiB aggregate decoded-skin limit.

This is static editor preview support. Frame/skin selection, animation, tag-based
model assembly, `.skin` remaps, scripted shader stages and shader-driven texture
selection are still missing. It does not extend the direct OBJ/GLB GUI importer,
convert class previews into imported meshes for engine exports, or provide a
native Quake III gameplay export. The Quake 3 profile remains experimental for
other reasons, including brush-primitive UV preservation.

Format references are the MD3 structures in
[ioquake3 qfiles.h](https://github.com/ioquake/ioq3/blob/main/code/qcommon/qfiles.h)
and normal decoding in id Software's
[misc_model.c](https://github.com/id-Software/Quake-III-Arena/blob/master/q3map/misc_model.c).
The implementation is a new Rust reader using these format definitions.

The original fixture is generated by
`examples/editor-checks/make_md3_fixture.py`. It has two surfaces, two distinct
frames, a tag and two 2x2 TGA textures, supplied loose, in PAK and in deflated PK3.
No commercial game assets are included. Regeneration reproduced all five fixture
files byte-for-byte locally.

Four reader tests cover exact geometry, normals, UVs, colors, fallback and bounds,
all truncations, single-byte mutations, bad indices, nonfinite UVs, versions,
counts and overlaps. The ModelStore test verifies parity across all three
containers, caching, explicit paths and no extraction. The document test mounts
the fixture with the actual Quake 3 profile, checks class scale and placement,
material pixels and supplied normals, and verifies model visibility filtering.
Native GUI rendering and actual game assets have not yet been visually checked.

Local verification on 16 October 2026 passed six focused MD3 tests and the wider
map_model/scene_export/editor_core library regression: 1,175 passed, 16 manual
benchmarks ignored. The full regression required localhost access outside the
socket-restricted sandbox. Both desktop and editor/export-worker wasm32 checks
passed with locked offline dependencies. Logs:
`/tmp/heron-md3-integration.log`, `/tmp/heron-md3-native-regression-host.log`,
`/tmp/heron-md3-web-check.log`, `/tmp/heron-md3-desktop-check.log`.
