# Importing static models

On desktop, use **Geometry → Import model**, or drop an OBJ/GLB file onto the editor. Heron inserts a point entity at the last map cursor position, snapped to the grid. The entity has a model preview and uses the model's actual bounds for selection. Import is one Undo step.

A saved map receives a copy under `.heron-brush/models/<content hash>/`. OBJ imports also copy the referenced MTL and base-colour image files. Dependencies must be inside the source model's folder. Sources stay untouched. Duplicate imports reuse identical asset files; Undo removes the entity and leaves reusable assets on disk.

An unsaved map initially references the source file. Saving it packages the assets beside the new map. Save As to another folder copies the referenced assets there and updates the references. Move the map together with its `.heron-brush` folder to move the project.

In a 2D view, the missing depth axis uses the reference selection's centre while retaining the cursor's other coordinates.

The entity's `origin` controls position, `angles` controls pitch/yaw/roll, and `modelscale` accepts one scale or three axis scales. The existing property inspector edits these values. OBJ starts at scale 1 in map units. GLB uses the glTF Y-up scene, converts it to the editor's Z-up axes and starts at 32 map units per metre. Adjust `modelscale` if your project uses different units. You may replace the default `heron_model` classname with your own game class and use the existing export class bindings.

Each triangle retains its material and any supplied vertex normals. OBJ diffuse textures and `Kd` colours, and embedded GLB base-colour images and factors, become separate skins. Textures keep their own dimensions and UV coordinates, including coordinates outside 0–1. Supplied normals use the inverse transpose under nonuniform or mirrored scaling. Missing OBJ normals use geometric face normals.

The common export build includes model triangles and a generated base-colour PNG for each used skin. Imported geometry therefore reaches engine targets without requiring a particular game script. The OBJ and portable glTF/GLB writers include it too. Static model instances can share geometry and retain their own transforms. Cases with collision, animation or custom pivots retain baked vertices. See [shared model exports](model-instancing.md) for the exact rules. No collision is generated by default. A project class binding can request concave mesh collision. Convex model collision is not implemented.

## Current limits

- Static OBJ and binary glTF 2 only. Direct `.gltf`, animated/skinned models, morph targets, sparse accessors and required glTF extensions are not supported.
- Base-colour materials and supplied smooth normals are preserved. GLB core PBR maps and factors are preserved in preview, Godot and glTF/GLB export; see [PBR support and checks](model-pbr.md). Material shader graphs and animations are not preserved. OBJ smoothing groups do not generate new normals; export vertex normals from the modelling tool.
- OBJ uses the existing fan triangulation reader. Export non-convex faces as triangles in the modelling tool. OBJ dependencies outside the model folder require reorganizing the source asset before project copying.
- Browser file import is not yet exposed. The shared model store now reads through the editor file hook, but uploading a model's dependencies into the browser filesystem still needs a workflow.
- Repeated model instances share editor caches and source assets. Static export instancing is implemented; collision, animation and mirrored engine cases retain baked geometry. Standalone OBJ remains flattened.

Local checks cover scene-axis conversion, node transforms, invalid GLB indices/lengths, project copying, exact Undo/Redo, entity rotation/scale, save/reopen, transfer through Save As and triangle output in all 13 targets. These format checks do not replace running each generated game. Native Linux checks also cover the import dialog, textured OBJ/GLB previews, inspector rotation/scale, exact Undo/Redo and reloading the saved map. Snapshots verify loaded triangles, texture dimensions and transformed bounds. OS drag/drop, complex production models and engine runs still need verification.
